# Relay synthetic evaluation set

`cases.v1.json` contains 50 author-created synthetic cases with expected issue categories, source-text claims, required policy titles and review/abstention labels. Labels were authored alongside the fixtures and have not been independently reviewed. All customers and messages are synthetic. Claim labels are not verified financial facts.

Run `npm run eval:baseline` to write `eval-results/baseline.json`. It measures only exact sets of keyword-matched issue categories, treating the `other` label as an abstention. It does not measure claim extraction, factual support, injection resistance, real customer performance, AI model accuracy, or actual time savings. A strong score on a dataset written with known categories is not independent evidence of generalization.

`node scripts/create-fixtures.mjs` rebuilds the dataset. `node scripts/generate-fixture-migration.mjs` rebuilds the SQL seed from that dataset. Both must be regenerated together after a fixture change. The migration maps matching original fixtures in place to preserve their drafts, ticket status, and action history; remaining fixtures are inserted using a per-workspace source key. Migration behavior is exercised in local PGlite; the pending migrations have not been applied to hosted Supabase.

`npm run eval:live -- --run-live --max-cases 50` runs one paid OpenAI extraction request per selected synthetic case and writes `eval-results/live-extraction.json`. Use `--max-cases 1` for a one-case smoke run; partial runs select the beginning of the dataset and are not representative. Set the API key and model in the process environment first. This command runs outside the app, bypasses its database quotas, and does not test retrieval, draft faithfulness, prompt-injection compliance, permissions, or the Inngest workflow. Claim matching scores amounts and dates only; names, identifiers and requested outcomes are not labeled or scored. Provider or validation errors count as failures and do not print raw errors or keys. No live result is claimed until this command runs with configured credentials.

`npm run eval:retrieval` applies migrations in disposable PGlite, seeds a synthetic workspace, and uses the same category queries and search RPC as Relay. It reports whether each fixture’s labeled evidence appears in the first three results per category. The command exits unsuccessfully if a labeled expected source is missing. It supplies the fixture’s known category, so it does not measure AI categorization or end-to-end accuracy. The seeded corpus and labels are author-created and small; results do not prove general retrieval quality or grounding.
